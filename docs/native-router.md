# Native router: behavior and evidence

This guide describes the Mod shipped in the plugin. Claude Code 2.1.321 is the minimum tested version. The router changes `model` and `effort` on main-conversation steps. Claude Code handles the Anthropic request, credentials, stream, tool execution, and cost ledger. Subagent steps keep their model and effort; the router chooses an agent's model once, at spawn, unless its definition pins one ([configuration](configuration.md#subagent-routing)).

## Turn behavior

At the first main step of a logical turn, the Mod reads recent message text and asks the active classifier (Jev, Clef, Clef Flash, Clef Omni, OpenAI, or Ollama) for a tier, and for the turn's activity unless `activityRouting` is `off`. It applies local policy and saves the route. Tool continuations reuse that route, except that a turn whose tool calls edit code moves up to the `code` route, and every `policy.reviewEveryRequests` requests a background classifier review may move it either way ([Changes during a task](user-guide.md#changes-during-a-task)). Before each continuation, context fit is checked again. A large tool result can move the step to a model with a larger window.

Claude Code sends a model change on every step, but an effort change on a tool-result step only when `CLAUDE_CODE_MODEL_CAPABILITIES=per_turn_effort` is set in its environment (the router does not set it). Without it a turn keeps the effort of its first request, so the band and the decision record can name an effort that did not run; see [what we do not know yet](activity-routing.md#what-we-do-not-know-yet).

The classifier receives the current prompt and at most six preceding user or assistant text messages. Each item is limited to 1,200 characters. It does not receive system messages, tool inputs, or tool results. Claude Code's Anthropic credentials never enter the classifier request. Jev, Clef, Clef Flash, Clef Omni, and OpenAI receive the text on their services; Ollama receives it on this machine. [Configuration](configuration.md#classifiers) lists each host.

The default tiers are defined in [Configuration](configuration.md#built-in-defaults). Policy uses vote hysteresis, repeated tool errors, context fit, model availability, and switching-cost estimates. The [architecture](architecture.md#request-flow) explains the event boundary and failure handling.

The activity is what the turn produces: `code`, `debug`, `explore`, `plan`, `review`, `ops`, or `docs`. A route is the tier's own route, the base route, with the activity's override on top. In `on`, the default since 1.7, it applies the overrides. The activity question reuses the same prompt and dialogue; no other text is sent. With `off` the classifier is asked for the tier only. [Route by activity](user-guide.md#route-by-activity) explains the modes, [Activity routing](activity-routing.md) the default matrix and its evidence, and [Configuration](configuration.md#activity-routing) the schema.

The prompt's typeahead (`prompt.autocomplete`) offers, from the first character typed after `/router `, the words that take no value and one row per value of the words that take one (`mode cost`, `engine shadow`, `release` with each model and account held now), because Claude Code asks only while a word is under the caret and passes a token that is never empty; after a word and a space, a letter narrows its values. The command, the typeahead and the argument hint all read one table, `lib/subcommands.mjs`, and a test runs the command with every word and value in it.

The route line is one `$.ui.place` row per routed turn, drawn by a `ui.render` hook on `Placed`. At `turn.complete` of the main loop, skipping an aborted turn, a subagent's turn and a turn with routing off, the router writes the route that ran (model, effort, tier, reason, activity and the policy's estimate, never text) to `$.state` under `router.lines` with the row's id (`rl-` and the turn id, made safe for `$.ui.place`), then places the row. The hook draws only rows whose `plugin` is the router's and leaves the rest to `next(e)`. A surface that cannot draw the row at that moment (`isPlaced: false`) is logged to the debug log and the turn goes on. Claude Code does not bring rows back on `--resume` and ends them at a compaction, so the records are not read again.

In a terminal, the pane's **Set up** and **Credentials → Edit** buttons open Claude Code's secure plugin configuration. The desktop app, VS Code and mobile cannot open that dialog, so there both buttons show a card with the command to run in a terminal (the band's **Set up** does the same). Claude Code refuses `$.command.run` from inside a `command.run` hook, so the Mod starts that dialog from a timer after the press returns.

Mode belongs to a Claude Code session. Clear starts a new session with routing on. Resume restores the saved mode for that session. A new or forked session has a new ID: it starts with routing on for a model that one of the tiers routes to and with routing off for any other model, as a fresh launch does. With activity routing `on`, a model that only an activity override uses also starts the session with routing on. A pin applies to one logical turn, then the prior route resumes. A history reset clears votes and cache evidence; the current turn keeps its route, pin and any native fallback.

## Router pane

In the terminal, the status band is one line above the prompt: a tier meter, the model, the activity, a short reason, classifier support and the switch cost, and context and cache use. Segments drop by priority when the band is narrow: classifier support and the switch cost first, then the mode and engine chips, then context and cache, then the activity, then the reason. Hovering shows, on the same row, a pin per tier, **Turn off**, and a two-row view whose second row shows the plan windows on a Claude plan and the session's cost against no routing; while routing is off, **Turn on** sits on the band itself, so the band carries one routing control at a time. A fresh session that starts with routing off because of its model shows `not a routing tier` on the band until the mode changes. The band yields to surveys. While subagents that the router routed are running, a row under the band lists them (`agents 2  ▸ ■ Haiku 5.5 Explore · retry usages ●`, at most three and then `+N`, never a teammate); pressing one opens that agent's transcript through `$.ui.view`, which Claude Code allows only as an answer to the person's own input, and a refusal is shown as a toast. The row is read from `$.agent.list()` joined with the router's spawn records, and redraws when the set of running agents changes (`subagentIds` in the view). In an agent's transcript the band starts with `◂ main`, which returns to the main conversation. In a subagent's transcript it names the agent's model and who picked it, such as `agent ■ Haiku 5.5  ↓ from Opus 5.5 (Claude Code’s pick)`; without a record of the agent it reads `agent · model chosen at spawn`, or `agent · keeps its own model (subagent routing off)`. A model change between turns raises a toast. A pin, or a step that changes only the effort, such as `medium` to `high` on the defaults, raises none. While the classifier runs, the turn's spinner says `Choosing model`. In Manual mode or when routing is unavailable, the prompt footer carries `routing off` or `routing unavailable`. The **Router** button opens the pane. In the terminal the pane has five numbered tabs, Now, Routes, Policy, Classifier, and Usage, under one `ROUTER` line with the routing on/off pair and the classifier state. The desktop app, VS Code and mobile draw a fixed one-row band, with nothing revealed on hover, and tabs without digits; see [the user guide](user-guide.md#in-the-desktop-app-vs-code-and-mobile). The [user guide](user-guide.md#open-the-router-pane) describes each tab.

The router keeps no bill. Routing vs no routing is a configured-price estimate, not a measured saving, and leaves out classifier charges and the side calls the router does not see; Claude Code's `/cost` counts those. See [Evaluation](evaluation.md) for what the available trace can support.

## Routing and classifier settings

The Routes tab edits tiers, activity cells and activity mode; Policy edits the start tier and four policy controls. Both share a draft that survives tab changes and closes but is dropped at a new session. **Save** validates the effective configuration and writes only the intended fields to the scoped plugin store; profile and project JSON files are read-only. An explicit built-in value can override a hand-edited value. The Classifier tab saves the choice and deadline at once. **Undo** is available until another write or a new session, and refuses to undo a record that another session has changed. See [Project routing settings](configuration.md#project-routing-settings) for precedence and [Save and undo changes](user-guide.md#save-and-undo-changes) for recovery.

| Control            | Values in the pane                 | Effect                                                                                   |
| ------------------ | ---------------------------------- | ---------------------------------------------------------------------------------------- |
| Deadline           | 500, 1,000, 1,500, 3,000, 5,000 ms | The active classifier's total advice time, including any transient retry. Saved at once. |
| Votes to go down   | 1, 2, 3                            | Consecutive votes for a downgrade; one before a history's first measured reply.          |
| Payback horizon    | 1, 3, 5, 10 turns                  | Later turns included in downgrade economics.                                             |
| Credits cap        | $0.50, $1, $2, $5                  | Largest estimated cold write on a `credits` model.                                       |
| Activity threshold | 50%, 60%, 70%, 80%                 | `policy.activityMass`: the least probability at which an activity applies.               |

The Routes tab starts with the **Activity routing** selector, `off · on`, and a hint for the mode, and a yellow line when the overrides do not run: activity routing is `off`, routing is off, or routing is unavailable. Below it is one grid of the draft: a column per tier, the **every turn** row with each tier's own route, and a row per activity whose cells show the route it runs (`models key·effort`, such as `sonnet·high`), `·` for the tier's route, `°` for a built-in default, and **●** for an unsaved edit. Each cell is a plain Button; selecting one opens its editor under the grid: a model and an effort Select, the cell's state, **Use tier model** to follow the tier explicitly, and **Restore default** for a changed or dropped built-in one. This stays with the tier when its model or effort changes, even over a built-in activity cell. Yellow notes flag a cell stronger than the tier above, and the only cell on its cache, which adds one; a cell equal to its tier's route but saved in the file says `no effect`. A line counts the prompt caches the routes use, one per model where efforts share a cache and one per (model, effort) pair where they do not, counting only tier routes until the mode is `on`, and another flags two neighbouring tiers with the same route. **Inherit tiers** removes stored tier routes and the start tier; pending activity and mode edits stay in the draft. The Policy tab writes each control inside its sentence and names the default beside a changed value, and ends with the `subagentRouting` mode, which is set in `router.json`. The Usage tab's breakdown by activity gives each activity's cost at list prices and the route it was `mostly on`; the Classifier tab's **ACROSS SESSIONS** adds the escalations after a cheaper activity move. The Usage tab's **Delete history** deletes the activity counts, the usage and the subagent records, for this session and across sessions.

The Classifier tab lists every configured classifier as a row with its service host (`this machine` for a local one), its activity probe and p95 wait, and whether its key and endpoint settings are complete. Selecting a row immediately saves the known classifier in the scoped plugin store and resets the new classifier's failure count. A turn already being classified finishes with its own classifier; its readings stay off the pane. **Undo** returns to the previous classifier. The deadline saves at once too, including explicit selections equal to built-in values. **Sends** names the host that receives prompt text. The **Deadline** line shows the active classifier's p95 wait across sessions, or its probe's before any turn, in yellow when it is slower than the deadline.

The Routes grid sizes its cells to the available pane width. Long labels use an ellipsis while retaining their
built-in/unsaved marker; select a cell to inspect its complete model and effort. Observed-only Usage rows retain
spend and tokens but show no fabricated savings. See [comparison coverage](user-guide.md#open-the-router-pane).

Project JSON links are refused, and invalid optional sources are ignored with a warning. New model aliases, provider dependencies and classifier definitions still require a hand edit to the active profile.

## Safety and failure states

- A missing key or account ID, a classifier failure, or a policy refusal keeps the current model. Network refusal is never bypassed with a helper process.
- A missing, malformed, or timed-out activity answer keeps the running activity in `on`; the tier answer still applies. It does not count as a classifier failure. If the whole classifier call fails, the running route stays. Activity statistics are written inside a guard: a failed store read or write loses that turn's counts and never fails a turn.
- Three launched classifier failures open a 60-second pause for that classifier. Each classifier has one in-flight request for turn decisions and one for mid-turn reviews in each active Mod instance, each with its own failure count and pause; spawns have their own count and pause but no in-flight slot. Pending host HTTP work blocks another request until it settles.
- A `router.json` with v0.8 gateway keys or the 1.1 `jev` section marks the router unavailable until the [migration command](configuration.md#convert-an-older-routerjson) converts it.
- Unsupported Claude Code versions and leftover v0.8 gateway settings (the `jev-router` model or the `127.0.0.1:43170` base URL) mark the router unavailable. `/router` lists the settings to remove. A local gateway does not run as part of this Mod.
- A session that starts with the router unavailable shows one toast with the reason (`$.ui.toast`, not `$.ui.notify`, which is a native terminal notification). It repeats at most once a day per cause: the time is kept in `$.store` as `notice:unavailable:<version|gateway|config>`. A `claude -p` run shows none.
- While the router is unavailable, the pane header reads `ROUTER  unavailable  Claude’s model is kept` with the reason, and offers no on/off pair or pins. `/router` without a surface starts with `Routing unavailable: <reason>. Claude’s model is kept.`, and `/router on`, `off`, `engine`, `pin`, and `activities` reply the same and change nothing.
- A context-window error makes that model ineligible until the next history reset. The Mod sends a request again only when a [model on probation](user-guide.md#when-a-model-fails) got no reply. A main turn that an API error ended, with something held for it, is [submitted again](user-guide.md#when-a-model-fails) as a new prompt, at most twice in a row.
- Unknown context retains the current model. There is no characters-to-tokens fallback.
- Unknown model substitutions receive no cache credit for the requested model.
- Clear, rewind, branch, or committed compaction clears cache evidence and policy votes. Resume restores the selected session's mode, not its old cache evidence.

## Verified checks

The Team canary loaded the published 1.0.0 package with a full Sonnet baseline, reached the real Jev endpoint, and kept Sonnet on a `downgrade-pending` result. This was a routing smoke test, not a measured-savings trial.

On 2026-10-05, live probes of Clef and Clef Flash on Workers AI took 0.7 to 1.3 seconds per call, one call each, and returned the same answer shape as Jev inside Cloudflare's envelope. A rejected token returned HTTP 401, which the Mod reads as a rejected key. No Clef session has been evaluated for routing quality.

Recorded acceptance checks cover the local HTTP deadline and one-request admission, session clear/resume, circuit-breaker pause, reload, replacement, unload, engine fallback, and interrupt during Jev advice. The interrupt check closed the loopback socket within 4 ms and discarded late advice without changing the active route or UI. Results are stored under [`experiments/mod-router/results`](../experiments/mod-router/results/).

On builds before 2.1.321, a billed chain of pinned turns moved across Opus, Haiku 4.5, and Sonnet with a tool call on every turn, and no request was rejected. Claude Code builds each model's request itself; Haiku 4.5 received its own thinking mode and a 32K output cap. On Claude Code 2.1.293, a turn pinned to `low` ran on Haiku 5.5 at `high` with a tool call and was served by the requested model (2026-10-08). Sonnet and Opus accepted histories above 589K input tokens. These probes validate the tested path only. Claude Code and organization policy control other model and request combinations.

To stop routing in a session, run `/router off`. To stop loading the Mod, run `claude plugin disable router@alexei-led-claude-router` and restart.
