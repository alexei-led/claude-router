## Rule, scope and counts

Use real `loadConfig` and `resolveRoute(config, tier)` for micro/low/medium/high, with **balanced semantics and no mode transformation**. Within each profile independently, capability for an exact model ID + effort is the highest rank of that profile's **BASE cells only**: micro 0, low 1, medium 2, high 3. Ignore activities entirely when assigning capability. Pairs absent from that profile's base routes stay unknown. No interpolation, effort offsets, half-steps, vendor ranking or model-card-derived numerical judgments.

The [accepted design](2026-11-16-auto-routing-design.md) describes the capability scale, and [CRITERIA](../../lib/classifier-contract.mjs) gives the task meanings. Base placement is policy intent, not evidence that a model meets those meanings. Unknown is not zero.

All five configured efforts for Haiku/Sonnet/Opus 5.5 and all three for DeepSeek 1017/GLM Flash/Kimi are listed, even if absent from every base route. There are **10 seeded profile/pair entries** (4/3/3), from **12 base cells**; all other catalog pairs are unknown. Anthropic `fable` is unused by these route/activity tables, so is outside the 24-row table but included as five unknown catalog candidates in simulation.
