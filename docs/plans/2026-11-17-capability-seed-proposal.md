## Method and scope

Resolve the three profiles using the real `loadConfig` and `resolveRoute` with **balanced semantics: no mode transformation**. For every distinct physical model ID + effort appearing in a tier's base route or effective configured activity override, take the **highest tier rank across all three profiles**: micro 0, low 1, medium 2, high 3. Every cited activity cell uses its merged effective route. An activity with no override simply inherits its base cell and adds no distinct evidence. There is no `applyMode`, `strength` offset, interpolation, half-step, vendor ranking, or benchmark-to-tier conversion.

The [accepted design](2026-11-16-auto-routing-design.md) uses this scale for declared capability, and [CRITERIA](../../lib/classifier-contract.mjs) defines its task meanings. Here a number records the maximum tier at which the existing tables place the pair, **not proof that it satisfies those task meanings**. `user-configured` means a seed derived from the effective profile tables, including inherited defaults explicitly labeled **inherited builtin**; it is not a low/medium/high empirical-confidence rating or a claim that the user authored builtin cells. All other pairs remain unknown, never zero. The previous two model-card-derived judgments are replaced entirely by this table-derived rule.

Counts: **24 unique supported-effort rows, 12 seeded, 12 unknown**. All five efforts for each of Haiku/Sonnet/Opus 5.5 and all three efforts for each custom routed model are present. No selected model lists `efforts: []`; an empty list would require one native-default row. Zero rows are inferred from mode-transformed efforts. The 12 base cells plus 45 explicit/effective activity override cells give **57 primary source cells**, resolving to **12 distinct seeded pairs**. Activity cells without an override inherit the corresponding base evidence.

## Expected balanced behavior and review decisions

Balanced roughly mirrors each tier base route's capability floor because that base pair is declared at least that tier. It does **not** reproduce table routing: the cheapest eligible qualifying candidate can differ, maximums collapse activity-specific uses, and global declarations cross profile boundaries. Constraints, cache cost, incumbent ties, switching gates and pins can change the result. Cost/quality use clamped −0.5/+0.5 demand margins, so they need not match balanced or each other. No route-quality, evaluation, savings, or equivalence claim follows.
